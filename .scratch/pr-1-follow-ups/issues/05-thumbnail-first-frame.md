# 面板首屏可能没有预览帧

State: closed
Scope: 已部署并复测

当前面板可见后才创建预览项，因此工作区或窗口卡片可能先显示占位内容，再填入缩略图。PR 还记录了提前创建预览后，在面板显示时因宽度变化导致预览重建的问题。

## 验证与处理结果

隔离 Quickshell 测试面板使用本机的 Wayland 抓帧。修复前，窗口首帧比面板显示晚约 161 ms，工作区静态和实时预览分别晚约 95 ms 和 62 ms。

长按确认且输入就绪后，面板按原时机映射并申请键盘焦点。可见的预览画面等到所选项和视口内的截图就绪再显示。180 ms 的定时器为无法完成抓帧的情况兜底。应用模式直接显示，快点提交不创建抓帧项。图标测量在画面显示后开始。相关约束见 #10、#11、#13。

部署后用已安装文件运行独立测试面板。窗口、工作区静态和工作区实时预览分别在映射后约 112、122 和 80 ms 显示，均在首帧就绪后。测试还覆盖滚动至最后一项、空工作区、缺少抓取源、应用模式、两种预览模式的快点，以及阻断抓帧时在画面出现前提交选择。阻断测试中，键盘在映射后 63 ms 就绪，兜底在 168 ms 显示画面。长按和释放时序由测试面板模拟。重启 Omarchy Shell 后，两个 IPC 入口和 12 条快捷键绑定均已验证。
