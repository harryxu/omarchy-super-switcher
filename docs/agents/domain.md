# Domain docs

This repo uses a single context. The glossary lives at the root in `GLOSSARY.md`, and architecture decision records live in `docs/adr/`.

- Before exploring the codebase, read the glossary and the ADRs relevant to the work, if present.
- Use glossary terms in issues, proposals, and test names. Record genuinely new terms through the domain-modeling skill when their meaning is settled.
- Cite the ADR and explain why it should be revisited if a proposal conflicts with an existing decision.
- Create glossary entries and ADRs as terms and decisions are settled.
